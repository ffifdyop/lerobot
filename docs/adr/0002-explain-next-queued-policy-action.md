# 以 RTC 接受后的下一入队策略动作作为 saliency 目标

RTC 会裁去新动作块的过时前缀，因此固定解释 a₀ 可能解释一个从未入队的动作。我们选择在推理前保存不可变重放输入，在动作块被接受且保留有效动作后，使用队列实际裁切索引 d 解释策略空间的 a_d；SmolVLA、π0 和 π0.5 两种 saliency 方法共用此身份契约。

该决定保留实时诊断能力，同时避免把未接受的 chunk 当作执行依据。被接受的动作仍可能因后续控制变化而不执行，所以它称为“下一入队策略动作”，不称为“实际发送动作”；覆盖全部最终执行动作需要额外消费追踪与延迟输出，留待后续。生成时估计的延迟必须原样用于重放，不能用事后裁切索引替代。

此决定已在首版实现。具体方案、风险与验收边界见 [OpenSpec 设计](../../openspec/changes/add-pi-rollout-saliency/design.md)，实测证据见 [验证记录](../../openspec/changes/add-pi-rollout-saliency/validation.md)。
